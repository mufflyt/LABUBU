# LABUBU — Mystery-Caller Study of Restorative Reproductive Medicine Practices

Secret-shopper (audit) study of Restorative Reproductive Medicine (RRM) practices.
Each practice is called once per **scenario** — *straight couple*, *lesbian couple*,
*single mother using donor sperm* — to test whether willingness to schedule and
time-to-appointment differ by caller identity.

- **Design:** within-practice; practice enters models as a random intercept.
- **Regulatory:** COMIRB 25-2596 · PI: Dr. Tyler Muffly, Denver Health.
- **Data source:** REDCap project **pid 39546** at `redcap.ucdenver.edu`.
- **Modeling engine:** the [`mysterycall`](https://github.com/mufflyt/mysterycall)
  R package (a separate repo; this one is an *analysis* repo, not a package).

## Provenance first

Every figure, table, and report in `mysterycall_outputs/` is fingerprinted in
**[`PROVENANCE.md`](PROVENANCE.md)** — which script wrote it, from which export,
on what date, at which git commit, under which package versions, and over which
denominator. That file is **generated by `provenance.R`, never hand-edited**, so
it cannot drift from the artifacts it describes.

Before quoting any *n* in a manuscript, abstract, or email, read
[the denominator cascade](PROVENANCE.md#2-denominator-cascade--read-this-before-quoting-any-n).
It is the single easiest number in this study to get wrong:

| Level | Rule | Used by |
|---|---|---|
| `all_records` | every row in the export | record counts only |
| `analytic_inclusion` | contacted-and-eligible calls | acceptance models, service rates |
| `wait_subset` | included **and** has an appointment date | figures 1–3, the LMM |
| `within_practice_pairs` | wait subset, practices with ≥2 scenarios | figure 4 |

Each level is roughly half the size of the one above it. Quoting the record count
under a wait-time figure overstates that figure's sample by about fourfold. The
live values are in `PROVENANCE.md`; they are deliberately **not** repeated here,
because a hardcoded copy is exactly how these numbers go stale.

## Refresh with a new REDCap export (the common task)

When a new export lands in `~/Downloads` (`LABUBU_DATA_LABELS_<date>.csv` and
`LABUBU_DATA_<date>.csv`):

```sh
Rscript refresh.R          # auto-detects newest export, runs everything, prints a delta
```

Or pull straight from the REDCap API, skipping the manual download:

```sh
Rscript refresh.R --pull   # needs REDCAP_LABUBU_TOKEN in ~/.Renviron
```

`refresh.R` copies the newest LABELS export into the repo, archives older exports
to `Old_redcap/`, runs the analysis, figures, and provenance, then reports what
changed (records, triads, missing single-mother calls, discordant pairs,
near-duplicate practice-name warnings).

To check call progress without a full re-run:

```sh
Rscript call_progress.R    # single-mother calls remaining / triads complete
```

## Models

- **Primary:** mixed-effects logistic regression (`lme4::glmer`),
  acceptance ~ scenario + (1 | practice).
- **Secondary:** linear mixed model, business-days wait ~ scenario + (1 | practice).
- **Matched:** exact McNemar (acceptance) and paired *t* / Wilcoxon (wait), each
  reported with a power/MDE statement. **These are the unconfounded comparisons.**
- **Sensitivity:** GEE.

## Settled analytical decisions (don't relitigate)

1. **The unmatched marginal acceptance comparison is confounded — do not report it.**
   Single-mother calls landed disproportionately at high-acceptance practices
   (~70% accept-everyone, vs ~14% at practices never called for a single mother),
   inflating single-mother acceptance to a misleading 64%. Within-practice, single
   mothers do slightly *worse*. Report only the paired analysis.
2. **Scenario comparisons are underpowered.** With ~11–13 discordant practices per
   contrast, only a roughly 4–6× odds ratio is detectable. Frame as exploratory,
   with the power floor stated explicitly rather than buried.
3. **Lead with the well-powered descriptives**, not the null scenario contrasts:
   service availability, overall offer rate, and concordance are estimated on the
   full included sample and are the study's most defensible findings.
4. **Finishing the single-mother arm is the highest-value remaining action.** It
   de-confounds the comparison and roughly doubles the effective sample. Targeted
   lists: `mysterycall_outputs/single_mother_calls_priority1_triads.csv` and
   `..._priority2_pairs.csv`.

## Gotchas

- **Practice-name normalization** (`normalize_practice()` in the eval script) is the
  sneakiest failure mode: a new spelling variant silently becomes a singleton and
  deflates the triad count. Every run writes
  `practice_name_review_nearduplicates.csv` and `_singletons.csv` and prints a
  warning. After a refresh, skim these and add a rule if two keys are the same
  practice. A few practice keys are phone numbers rather than names; those can
  never match a triad partner and need fixing in REDCap, not in code.
- **Analytic inclusion is `Reason for exclusions`, not `Complete?`.** As of the
  2026-08-02 export every record is marked Complete, so `Complete?` no longer
  discriminates at all and must not be used as a denominator.
- **Raw exports are gitignored** (`LABUBU_DATA_*.csv`) because they carry practice
  contact information. Keep them out of commits. The API token belongs in
  `~/.Renviron` — outside the repo — never in a project-level `.Renviron`, which
  is not gitignored.
